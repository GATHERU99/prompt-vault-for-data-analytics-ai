# GitHub Repo Audit Template

## Purpose

Use this prompt to quickly evaluate whether a GitHub repository is worth learning from, using, forking, adapting, or monetizing.

---

## Prompt

Act as a Senior Software Architect, Data Analyst, Product Strategist, and Open Source Evaluator.

I will provide a GitHub repository link.

Repository:
[PASTE REPO URL HERE]

Evaluate the repository using the following framework.

---

## 1. Quick Summary

Explain in simple terms:

- What the repository does
- Who it is for
- The main problem it solves
- Whether it is beginner-friendly or advanced

---

## 2. Learning Value

Score: /10

Evaluate:

- What skills I can learn from it
- Whether it improves my data, AI, coding, or product-building ability
- Whether the documentation helps me understand the project
- Whether it is worth studying line by line

---

## 3. Code Quality

Score: /10

Evaluate:

- Project structure
- Readability
- Naming conventions
- Modularity
- Error handling
- Testing
- Maintainability

Red flags:
- Messy folder structure
- No documentation
- No tests
- Hardcoded secrets
- Abandoned code
- Too many unresolved issues

---

## 4. Documentation Quality

Score: /10

Evaluate:

- README clarity
- Installation instructions
- Usage examples
- Screenshots or demos
- API documentation
- Contribution guide

---

## 5. Business Potential

Score: /10

Evaluate whether this repo could become:

- SaaS product
- Internal business tool
- Client service
- Portfolio project
- Automation workflow
- Lead magnet
- Paid template
- Consulting offer

---

## 6. Monetization Opportunities

List practical ways to monetize it.

For each idea, include:

- Monetization model
- Target customer
- Difficulty level
- Estimated time to MVP
- Risks

---

## 7. Reusability

Score: /10

Evaluate:

- Can I fork it?
- Can I adapt it for my own use?
- Can it support Metacom Virtuals?
- Can it support data analytics work?
- Can it become a portfolio project?

---

## 8. Setup Difficulty

Score: /10

Evaluate:

- Installation complexity
- Dependencies
- Required technical skill
- Hosting requirements
- Whether a beginner can run it

---

## 9. Red Flags

List anything that should make me cautious.

Check for:

- No license
- Poor maintenance
- Security risks
- Outdated dependencies
- Unclear ownership
- Weak documentation
- Too complex for current skill level

---

## 10. Final Scorecard

| Category | Score |
|---|---:|
| Learning Value | /10 |
| Code Quality | /10 |
| Documentation | /10 |
| Business Potential | /10 |
| Reusability | /10 |
| Setup Ease | /10 |

Total Score: /60

---

## 11. Final Recommendation

Choose one:

- Study it
- Fork it
- Use it
- Adapt it
- Monetize it
- Ignore it

Explain why.

---

## 12. 30-Minute Action Plan

Give me a practical next step plan:

### First 5 Minutes
What should I inspect first?

### Next 10 Minutes
What files should I read?

### Next 10 Minutes
What should I test or run?

### Final 5 Minutes
What decision should I make?

---

## Output Rule

Be brutally honest. Do not overhype the repository. Focus on whether it is useful for my growth in data analytics, AI, automation, and business building.
